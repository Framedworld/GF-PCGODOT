# WP13-R2: adversarial review of spatial data and terrain adapters

Reviewer R2. Scope: `spatial/*.gd` (every `FlowSpatial` shape, `FlowTriangleGrid`,
composites, `FlowSurfaceLayers`, `FlowSpatialSources`), `terrain/*.gd`, and the
nodes that use them: `surface_sampler`, `volume_sampler`, `sample_spline`,
`to_point`, `get_spline_data`, `get_surface_data`, `get_volume_data`,
`get_bounds`, `make_bounds` (Shape), `create_surface_from_polygon` /
`create_surface_from_spline` (Shape), `projection` (Surface),
`difference` / `intersection` / `union` (shape paths, `overlap_mode`) and
`filter_data_by_type`.

Method: read the area end to end, list failure hypotheses, write a
deterministic headless test for each before touching the code, fix only what
failed (smallest change, one commit per bug), keep the passing tests that add
coverage. All new tests are in
`demo/tests/spatial/wp13_r2_spatial_review_test.gd` (26 cases: 18 regression, 8 coverage).

### Output changes and hashes

- Golden and seed-zero baselines: unchanged, no regeneration (the golden
  summary does not include shape content hashes; no golden graph exercises a
  changed path).
- Changed point output, only for inputs that were wrong before: BoundsBox on
  non-Y-up surfaces (2), merged soft volumes and splines (3), To Point on
  merged splines (4), normals and aligned rotations of level nearest-point
  projections (5), Union / Symmetric Difference with an empty point pin (10),
  non-uniformly scaled spline tubes (11), Terrain3D surfaces whose two
  spacings differ (9), and sampler errors where it used to hang or return
  nothing silently (1, 8).
- Changed content hashes without changed densities: merged volume and spline
  unions (their density function is now in the hash, 3), unions of four or
  more shapes (tree shape, 7). Every union density function in use (Binary,
  max) is exactly associative, so densities, kinds, bounds, leaf order,
  projections and layers are unchanged. Multiply and Subtract are associative
  too, but a rebalanced tree can differ in the last float bit; no stock caller
  passes them to `union_of`.

## Suspected issues, not fixed

- **Shapes are only immutable by convention.** Public fields are packed arrays
  and objects shared by reference: `var a := poly.polygon; a[0] = ...` changes
  the shape (demonstrated) while its Z bands stay stale; the same holds for
  `FlowHeightfieldSurface.heights`, `FlowSplineShape.curve` (a live Curve3D),
  `grid.vertices`, `FlowPointsVolume.box_*` and `FlowSurfaceLayers.grids`. No
  code in the repository writes them (grep), so nothing is broken today; making
  them private is an API change.
- **Bounds of non-Y-up surfaces.** An XY / YZ polygon (or tilted heightfield)
  has infinite density along its local Y, but `get_bounds()` is the outline.
  Composites take their bounds from the operands, so for example
  Intersection(XY polygon, a volume off the plane) has empty bounds and samples
  nothing while `sample_density` is 1. WP2 already lists vertical walls as a
  limitation; fix 2 covers the direct point-versus-shape case only.
- **Scaled splines measure in curve units.** `to_points` intervals and the
  `spline_length` attribute use the curve's own length, so under a scaled
  Path3D (even uniformly, scale 2) points are `interval * scale` apart in the
  world. Probably consistent with the legacy `sample_spline` Path3D path; not
  changed because it alters output and may be intended.
- **Splat weights are not clamped.** `FlowSurfaceLayers.from_images` keeps raw
  channel values, so a float splat image outside 0..1 breaks the
  `get_layer_weight` "0..1" contract (native Terrain3D weights are clamped).
  Textures-mode `sample_terrain_layers` does not clamp either, and WP6 tests
  bit-equality between the two, so I left both alone.
- **Shapes through unrelated nodes.** `merge` drops `Data.shape` (and tags)
  without a warning; attribute `filter` sends a shape-only Data to both its
  Inside and Outside pins. Not my files; a warning in `merge` would be cheap.
- **Union cost.** A union of N shapes costs O(N) per density query (no index
  over operands); a merged source with thousands of colliders samples slowly.
- **HTerrain fingerprint** reads splat texels with `Image.get_pixel` without
  decompressing (the layer builder does decompress); a compressed splat image
  would print errors on every fingerprint.
- `FlowHeightfieldSurface` itself still clamps a cell size <= 0 to 1e-6
  silently (the node now rejects it).

## Judged fine (tested or checked)

- `FlowTriangleGrid.nearest` and `vertical_hit` match brute force on random
  queries inside, outside and exactly on cell boundaries, with degenerate and
  collinear triangles in the soup (`test_triangle_grid_matches_brute_force_on_random_queries`);
  the ring lower bound is sound (per-cell bound covers triangles registered in
  several cells, the projection bound holds for queries outside the grid).
- Polygon point-in-polygon equals brute-force even-odd on random concave and
  self-intersecting polygons, both windings, probes level with vertices
  (`test_polygon_contains_matches_brute_force_any_winding`).
- `box_overlap` peaks are exact (never below dense sampling) for axis-aligned
  boxes with mirroring and non-uniform scale and for rotated, mirrored true
  spheres; hard-box coverage equals the overlapped volume fraction
  (`test_box_and_sphere_overlap_match_dense_sampling`).
- Heightfield indexing: last row and column, non-square grids, origin offsets,
  past-the-edge misses; normals under non-uniform scale and mirroring use the
  inverse transpose and are correct (probe). `HeightMapShape3D` row-major
  `z * width + x` layout and centring match Godot's physics convention.
- Mesh volume parity: 3 000 probes, a third of them on grid lines, against an
  analytic box (probe).
- Concurrent queries from 20 worker tasks over spline, mesh, heightfield,
  composite and points-volume shapes equal sequential ones
  (`test_concurrent_queries_match_sequential_ones`); shapes do not change when
  the source Curve3D is edited (`test_editing_the_source_curve_does_not_change_the_shape`).
- `falloff` is continuous, monotonic, 0 beyond 1 and for NaN
  (`test_falloff_is_continuous_and_monotonic`); `content_hash` changes with
  every parameter of splines, heightfields, boxes, spheres, polygons and
  composites and is stable (`test_content_hash_covers_every_parameter`).
- Composites of a shape with itself and three-deep nesting follow the density
  table (`test_shape_combined_with_itself_and_nested_composites`).
- Terrain adapters: every Terrain3D and HTerrain plugin call is guarded by
  `has_method` or an `in` check, or by detection (which requires the method);
  edge clamping, NaN holes and one-sided normals are as documented.
- Nodes with broadcast (length-1) density, size and rotation streams
  (`difference`, `get_bounds`, `projection`), empty inputs, kind-only empty
  spatial Data in `filter_data_by_type`, and sampler determinism under seeds
  (probes). The surface sampler places one candidate per world cell; on a
  100 x 100 m plane at 0.5 / m^2 with no jitter it keeps 5 041 cell centres
  (71^2) against 5 000 expected, a boundary effect of under 1 %.

## Limits

- The Terrain3D and HTerrain adapters were again exercised only against the
  fakes in `tests/terrain/support/`; no real plugin.
- This repository's GdUnit runner stops a suite at its first failing test, so
  the failing-first check was done per test by running a copy of the suite
  with every other test disabled.
- Precision: polygons and positions are single precision (`Vector2`,
  `Vector3`), so at 1e6 m the resolution is about 0.06 m; inherent to standard
  Godot builds, not tested further.
- No editor or visual checks.
