## 1. `dungeon_connect_rooms`: input without a position stream

`nodes/dungeon_connect_rooms.gd`. `size()` is the length of the first stream, so input with two or more rows but no `position` stream passed the size check, and the node then indexed an empty array. Now:
- input with fewer than two rows still gives an empty output, without an error (unchanged);
- otherwise, input without `position` gets `setError("Input must provide a position stream")` and no output.

The conformance harness no longer needs its known-bug row for this case. The `dungeon_connect_rooms` row in `tests/executor/conformance/conformance_overrides.gd` is removed, so the harness now also runs the `attr_set` case.

Test: `tests/stabilization/dungeon_connect_rooms_position_test.gd`, 3 cases.

## 2. `points_from_imported_scene` / `load_alembic_file`: node transforms

`nodes/points_from_imported_scene.gd`; `load_alembic_file.gd` extends it, so it gets the fix too.

**Before.** `_append_mesh_point` read `mi.global_transform` on an instance that never enters the tree. Godot logged `Condition "!is_inside_tree()" is true` and returned the identity transform. Every point's position, rotation and size therefore ignored:
- the MeshInstance3D's own transform;
- every parent's transform, the root's included.

**Now.** `_walk_meshes(node, parent_xform, parent_is_3d, ...)` accumulates the local transforms from the instance root down. This reproduces what `global_transform` would give if the instance were added under an identity parent, including Node3D's own rules:
- a Node3D composes with its parent when the parent is a Node3D;
- a `top_level` Node3D, or one whose parent is a plain `Node`, starts from its own transform.

The root's own transform is applied. The engine error is gone.

**Test.** `tests/stabilization/imported_scene_transforms_test.gd`, 3 cases. A scene is built in code and saved to `user://`. In it, a mesh is nested under a rotated, scaled and offset pivot, under a rotated and offset root. The scene also has a mesh under a plain `Node` and a `top_level` mesh. The checks are:
- a known value: root × pivot × mesh applied to the box centre, and the scaled size;
- for both templates, a comparison with the same scene instanced in the running tree and read through `global_transform`.

**Output change (intended).** Scenes whose meshes are not at the root's origin with identity rotation and scale now give different positions, rotations and sizes. No demo graph uses either template, and the golden suite does not cover them. See the DEPRECATIONS rows.

## 3. `bounds_from_mesh` traits, and warnings for meta overrides

**Before.** `nodes/bounds_from_mesh.gd` declared `"pure": true, "main_thread": false` in its `meta_node`. That overrode its traits table row `[main_thread = true, cacheable = false]`, so the node ran on the pool and was cached. The risk was `PrimitiveMesh.get_aabb()`: on a mesh with a pending change, it runs the lazy update on the worker thread.

**Now.** The meta declares `"main_thread": true, "pure": false`, the preferred option, which agrees with the table row. Its output is unchanged. The node is only no longer threaded or cached.

**Warnings.** `FlowNodeTraits.resolve` still lets `meta_node` win. When the result differs from the template's table row, it now prints a `push_warning`, once per template:

> FlowNodeTraits: meta_node of '<template>' (<flags>) overrides its traits table row [...]; effective [...]

- `FlowNodeTraits.override_warnings()` returns the warned templates and texts, and `clear_override_warnings()` resets them.
- No stock template triggers the warning now. A test checks this over every table row.
- Third-party templates without a row never warn.
- Warnings are raised where traits are resolved: `FlowCompiledGraph` on the main thread. Pool elements hit the per-template cache.

The `bounds_from_mesh` note in `conformance_overrides.gd` was updated. The conformance suite stays green: the template now runs checks 1 and 2 only, as a main-thread template.

Test: `tests/stabilization/traits_meta_override_test.gd`, 4 cases.

## 4. Set-operation broadphase: full box sizes

**The bug.** `nodes/difference.gd` `_broadphase_params` passed half extents to `GDRTree.add` and `overlaps`. Those take **full** sizes: the native code builds `center ± size * 0.5`. So every point that carries `bounds_min` / `bounds_max` (surface sampler output, `bounds_modifier`, `bounds_from_mesh`, ...) took part with a box half its size on every axis. Points with plain `size` were correct.

**The fix.** `_broadphase_params` now returns `{centers, sizes}` with full sizes, clamped to at least 0.0001. The narrowphase (`_attenuate_difference`) already used full world boxes.

**Other callers.**

| Caller | Status |
|---|---|
| `intersection.gd`, `union.gd` | Extend `difference.gd`, so they share the fix. |
| `self_pruning.gd` | Already passed full sizes. Covered by a test, unchanged. |
| `substract.gd` (legacy) | Passes the `size` stream directly and ignores bounds streams. That is correct for what it reads, so it is unchanged. |
| `relax.gd`, `point_neighborhood.gd` | Pass full sizes. |

**Test.** `tests/stabilization/set_operation_broadphase_test.gd`, 4 cases. Random boxes (60 per side, several seeds) are compared with a brute-force AABB overlap computed independently of the node code. The four pairings are bounds/bounds, bounds/size, size/bounds and size/size. The size streams on the bounds side deliberately disagree with the bounds. The checks are:
- `difference` A−B and B−A;
- `intersection`, and difference's Intersection operation;
- `union`, which keeps all of A plus the B points that touch no A box;
- `self_pruning`, against a greedy input-order reference.

Each test was confirmed to fail before the fix, except `self_pruning`, which was already correct.

**Output change (intended).** It affects graphs where a point side that carries bounds streams meets `difference`, `intersection` or `union` with point inputs. Shape inputs use a different path and are unaffected.
- **Golden diff: none.** The golden and seed-zero suites pass unchanged.
- **Demo graph affected at run time:** `graphs/graph_hierarchical.tres`, the FlowWorld3D demo, where `rocks_clear` is the difference of surface-sampled rocks (±0.6) against trees (±2). Rocks are now removed wherever their box overlaps a tree's full box, up to 2.6 m apart instead of 1.3 m (WP5.md).
- **Why no baseline sees it.** The golden harness runs that graph without its ground surface, so `rocks_clear` gets empty input. The seed-zero suite hashes the demo scene before the demo's generation source starts (after 30 frames).
- The world tests (`tests/world`) assert only what holds either way, and they pass.

## 5. Threaded mode and script Loggers

**The hazard.** Errors that do not go through `setError` reach every script `Logger` (`OS.add_logger`) on the pool thread that raised them, possibly from several threads at once. That covers a `FlowData` helper's `push_error`, `push_warning`, and engine errors. WP9 hit heap corruption with GdUnit's non-thread-safe logger. Third-party Loggers cannot be made thread-safe from here.

**Documentation.**
- `demo/addons/flow_nodes_editor/README.md`, threading section: a "Warning: script Loggers and threaded mode" block.
- The `FlowGraphNode3D.threaded` export tooltip (`flow_node.gd`).
- The `FlowExecutor` THREADED header comment.

**Batching rule.**
- `FlowNodeTraits.LOGGING_TEMPLATES` lists the threadable stock templates the conformance harness recorded logging outside `setError` (WP9.md: "Errors printed outside setError", the "batched" cases, and the `@last` defaults note):

| Template | What it logs, and on which input |
|---|---|
| `relax`, `snap_to_grid` | `cloneStream` without `position` |
| `point_filter_range` | `findStream` on an attribute set |
| `mutate_seed` | a warning without `seed` |
| `boolean`, `filter`, `partition` | `translateStreamName`: `@last` on Data without streams |

  (`points_from_imported_scene` and `load_alembic_file` are main-thread templates, and item 2 removed their error.)
- `FlowNodeTraits.logs_outside_set_error(element)` reads that list. `meta_node["logs"]` overrides it either way, for third-party nodes.
- `FlowExecutor.split_batch(ordered, batch)` splits a batch of ready threadable elements into `serial` and `pooled`, both in batch order.
- In `_run_threaded`, when at least two pooled elements remain, the serial ones run first, one at a time, on the calling thread, while no pool task runs. Then the pooled ones run as a concurrent group, as before. A batch with fewer than two pooled elements runs entirely on the calling thread, in order.
- `FlowExecutor.serialized_element_count` counts the serialized elements.
- Outputs and the order of `last_errors` are unchanged: errors are still buffered per element. The executor modes golden test passes.

**Test.** `tests/stabilization/threaded_logging_batch_test.gd`, 4 cases:
- the flagged templates, and that they are threadable;
- the meta flag;
- `split_batch`;
- a graph with 4 `relax` and 4 `transform_points` branches run threaded. Its output equals the sequential run, exactly 4 elements were serialized, and exactly 4 ran on the pool.

**Residual exposure.** Any other pure node can still print an unforeseen engine error from a worker. This is stated in the README.

## 7. `spawn_spline_mesh` and composite spline data

**Before.** `get_spline_data` with `output_mode = Merged` outputs `FlowCompositeShape.union_of(shapes)`, which reports `Kind.Volume`. `splines_from_shape` rejected it, so a merged input spawned nothing, or gave the "no spline shape" error.

**Now.** `splines_from_shape` walks composites. It recognises them by duck typing (`op`, `a`, `b`), like the rest of the hook. The documented order is depth first, `a` before `b`:
- **Union and Intersection:** the spline parts of both operands.
- **Difference:** the spline parts of `a` only, because `b` is subtracted.
- Non-spline parts are skipped.

A merged union (a left fold) therefore yields its splines in Path3D collection order. The set operation does not clip the spawned meshes: every spline part is spawned whole. This is documented in the function comment.

Test: `tests/stabilization/spline_mesh_composite_test.gd`, 4 cases:
- a union in merge order (curve and source identity);
- difference in both orders;
- intersection and nested composites, and a composite without splines;
- end to end, `get_spline_data` Merged over three Path3Ds into `spawn_spline_mesh`, which spawns all 5 segments.

## 8. Scoped `FlowGraphNode3D.cleanup()`

**Before.** `cleanup()` walked its own subtree. It then walked the owner's, or the parent's, **whole subtree** to find content spawned outside it, through `spawn_parent_path` or a target node. Under `FlowWorld3D`, every cell cleanup therefore scanned every sibling cell's content.

**Now.**
- **Tagging.** `FlowNodeBase.tagFlowContent(node, ctx)` (`node.gd`) stamps the `flow_owner` meta and records the node on the component through `note_spawned_content`. Every stock tagging site uses it:

| Where | Call |
|---|---|
| `FlowSpawnUtil.claim_spawned` | through `tagFlowContent` |
| `spawn_meshes.spawnNode`, `spawn_nodes`, `spawn_scenes`, `spawn_spline_mesh`, `create_spline`, `create_target_node` (2 places) | `tagFlowContent` |

  The meta value is unchanged.
- **Cleanup.** `cleanup()` first walks its own subtree, exactly as before. Legacy String metas and stale component ids still count there (docs/RUNTIME_API_P0.md §5). It then checks only the **direct children of the parents of the recorded content** that lie outside its subtree. Content roots sit directly under their spawn parent.
- **Records.** They are cleared by `cleanup()`. Freed ids are compacted as records grow. `recorded_content_count()` and `last_cleanup_visits` are exposed for tests and diagnostics.
- **Back-compat for third-party spawners.** A direct `flowOwnerMeta(ctx)` call cannot say where the content goes. It therefore calls `note_untracked_content()`, and that component's next cleanup falls back to the old owner or parent scan.

**Benchmark.** `godot --headless --path . -s res://tests/perf/cleanup_benchmark.gd` builds 200 cell components under one parent. Each runs grid 5×5 → `spawn_nodes`, for 5000 spawned nodes in total. Then every component is cleaned up. Three runs each:

| | Total for 200 cleanups | Per component (median) |
|---|---|---|
| Before | 1218 / 980 / 990 ms | 4.95 ms |
| After | 24.1 / 24.6 / 25.0 ms | 0.123 ms |

That is about 40 times faster. Before, the total grew with the square of the cell count.

**Tests.** `tests/stabilization/scoped_cleanup_test.gd`, 4 cases:
- one of 20 sibling cells visits only its own 9 nodes;
- an external `spawn_parent_path` shared by two components;
- the untracked fallback;
- records are released.

All existing cleanup tests pass unchanged: `runtime_api_test`, `create_target_node_test`, `spawn_pool_test` and the world manual API tests.

## 9. `grid_fill_bounds` `world_anchored`

New setting `world_anchored : bool = false`. It is appended after `max_points`, so exposed-parameter port indices of saved graphs do not move.

When it is on, each axis takes every `k * cell_size` with `min <= k * cell_size <= max`, with a 1e-4 cell tolerance on both edges. This replaces `round(size / cell)` points centred on the box. The rules:
- Positions depend only on `k` and the cell size, so adjacent boxes and FlowWorld3D cells share one world grid.
- The cull node's half-open ownership removes the shared edge points.
- A box that contains no multiple on an axis gets no cell.
- Without `fill_y_axis`, the single layer stays at the box centre's height.
- Seeds are position-hashed, as before.
- The default output is unchanged.

**Test.** `tests/world/grid_fill_world_anchored_test.gd`, 4 cases. The WP5 world harness gains a `grid_fill_anchored` kind in `tests/world/support/world_test_util.gd`; the existing kinds are unchanged. The test checks:
- partition invariance: 16 cells against the monolithic run, seeds 0 and 4711, more than 50 points;
- the default placement;
- anchored X/Z placement, and an empty thin box;
- anchored Y with `fill_y_axis`.

`test_samplers_that_are_not_world_aligned` still lists the default `grid_fill`, which is still not aligned.

## Left undone and limits

- **Item 5 is a mitigation, not a fix.** Only templates known to log are serialized. An unforeseen engine error from another pure node on a worker still reaches Loggers concurrently.
- **Item 7 does not clip meshes.** Spline parts of an intersection or difference are spawned whole; the composite's other operand does not clip the meshes.
- **Item 8 does not find hand-stamped content.** Content stamped by hand with a `{component: id}` dictionary outside the component's subtree, without `tagFlowContent` or `flowOwnerMeta`, is no longer found by `cleanup()`. No stock code does that.
- **Item 6 tests the plugin hooks by reading the source.** An `EditorPlugin` cannot be entered headless, so `_enter_tree` and `_enable_plugin` are checked by a source scan; `register_project_settings()` itself is executed.
- **The conformance report in WP9.md was not regenerated.** `tests/executor/conformance/tools/conformance_report.gd` was run on this branch (167 templates, 2244 fixture cases, 555 pass, 0 fail, 113 skip) and shows:
  - no known-bug cases;
  - `bounds_from_mesh` as main (meta);
  - no "meta_node disagrees" rows;
  - no `points_from_imported_scene` / `load_alembic_file` console errors.

  The coordinator can paste that output into WP9.md.
