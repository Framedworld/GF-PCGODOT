# WP13-R5: adversarial review of attribute types, WP4a/WP4b nodes, loop and subgraph

Reviewer R5. Scope: the attribute-type machinery in `flow_data.gd` (DataType additions, containers, `registerStream` type checks, selector aliases, component selectors), `attributes/flow_attribute_ops.gd`, the WP4a nodes and the old nodes it extended, the WP4b nodes, and `nodes/loop.gd`, `subgraph.gd`, `get_loop_index.gd`, `get_loop_key.gd`.

Method: I read the area end to end and listed failure hypotheses. For each one I wrote a headless, deterministic test first. When the test failed I made the smallest fix and committed it with its test, one commit per bug. Tests that passed were kept only where they add coverage that did not exist before.

Base: `d5bd9b6` (`origin/claude/pcg-system-review-4tpca9`). There are 16 commits on the worktree branch: 15 fixes and 1 coverage-only commit.

### Output changes for existing graphs

The golden and seed-zero suites pass unchanged; no baseline was regenerated. Outputs change only in these cases:
- `compare_op` with two integer operands and a user tolerance of 1 or more: integers within the tolerance used to compare equal. They now compare exactly, which is what the node's tooltip and WP4a.md document.
- Inputs that used to produce a script error and no output (rows 5, 6, 7 and 15) now produce output.
- Loop Merge of multi-point results with broadcast streams (row 9): values that were corrupted are now correct.
- Loop Partitions over Int64 or Double attributes (row 11): the per-data attribute and the bindable parameter keep full precision.
- Zero quaternions become identity quaternions (rows 12 and 13).
- Inverting a singular transform (row 14).
- A self-recursive graph now leaves an error in `last_errors` (row 10).

Suggested DEPRECATIONS row (section 2): `compare_op`, integer == / != with tolerance ≥ 1 | integers within the tolerance compared equal | integers compare exactly | WP13-R5.

## Confirmed or suspected issues, not fixed

1. **`get_loop_key` truncates Int64 and Double keys.** Confirmed by reading the code. The key arrives as a bare `int` or `float` runtime parameter, `_inferValueType` maps it to Int or Float, and the value wraps or rounds. Fixing it needs the key's type to travel with the key (for example a new `iteration_key_type` parameter), which is a contract change. Per-data attributes and bindings are fixed (row 11).
2. **Exponential work under self-recursion.** The depth guard holds and now reports an error, but a self-referencing loop with N iterations per level still runs about N^20 nested evaluations before every path reaches the guard. Ancestry-based cycle detection would also stop bounded recursion over a shrinking input, so I did not add it. A lower depth limit, or an evaluation budget, is worth considering.
3. **Zero quaternions are still reachable** through `attribute_cast` Vector4 → Quaternion (documented as "not normalised") or a hand-made zero Vector4 stream. Downstream, `make_transform_attribute` builds `Basis(Quaternion(0,0,0,0))`, which is NaN. Separately, `break_transform_attribute` and `lerp_transform` on a zero-scale basis call `get_rotation_quaternion`. That logs engine errors, although the result (identity) is sane.
4. **`attribute_select` with NaN values** uses the same kind of comparator as the loop bug in row 8 (`keys[a] < keys[b] or …`). Min, Max and Median may depend on input order when a value is NaN. Not tested.
5. **`Data.size()` reads the first registered stream.** A Data whose first stream is a broadcast stream reports 1 point to every node. This predates the round and is not specific to this area.
6. **`attribute_set_to_point` with `transform_attribute_name`** writes position, rotation and size but leaves a stale `rotation_quat`, which wins over `rotation` when point bases are built. The older non-transform path has the same pattern.
7. **Selector alias edges:**
   - `create_points` refuses canonical attribute names but accepts `$Density`, which then writes `density` through the alias.
   - `first("$Density")` does not fall back to a per-data attribute `density`.
   - `@Source` on `$Index` creates a stream literally named `Index`.
   - A literal `$Position` stream can only exist through direct `streams[...]` assignment; `filter` or `emptyLike` would rename it through the alias.
8. **`compare_op` AnyComponent with `!=`** gives "no component equal" rather than "some component differs". This is a semantic choice; I did not check it against UE.
9. **Type-gated attributes.** `split_points` (`split_position_attribute`) and `weighted_point_sampler` (`weight_attribute`) refuse Int64 and Double attributes, although both nodes can read them.
10. **`expression` result type.** The type of the first point's result fixes the container type for all points. This predates the round.

## Judged fine

- **Casts:** NaN to 0; ±INF and out-of-range values clamp to the Int64 limits; Int64 → Int wraps or clamps; NaN → Bool is true (as in C++).
- **`bitwise_op`:** shifts are arithmetic and clamped to 0..63; Not.
- **`vector_op`:** zero-vector normalize, project and reflect, parallel cross, lerp outside 0..1.
- **`trig_op`:** clamps the inputs of Asin and Acos, as UE does.
- **`compare_op`:** NaN is never equal; broadcast B.
- **Strings:** Replace with an empty pattern is the identity; unicode and regex characters are handled.
- **`merge_attributes`:** numeric promotion is order-independent.
- **Determinism:**
  - `weighted_point_sampler` and `discard_points_on_irregular_surface` are invariant under reordering.
  - `split_points` has no randomness.
- **`find_convex_hull_2d`:** single, duplicate, collinear and edge points; points far from the origin.
- **`filter_data_by_index`:** syntax edges (`''`, whitespace, `1:1`, `5:2`, out-of-range values, negative bounds, `:`, malformed tokens).
- **`create_points`:** Local space with no owner falls back to world space.
- **Runtime quality nodes:** unknown level names fall back to the project setting.
- **Mutation:** no node in the area writes into its input's containers. Every node works on `duplicate()` or `filter()`, and `copy_meta_from` deep-copies `data_attrs`.
- **Loops:**
  - Per-iteration runtime parameters do not leak into the parent context (the child gets a deep-duplicated copy).
  - `ctx.seed` is restored after each iteration, and main-thread elements never run concurrently with the pool.
  - `chunk_size` of 0, negative, 1, or larger than the input.
  - Empty inputs.

## Limits

- No editor or inspector UI was exercised.
- Threaded and cached modes are covered only by the existing executor suites, which pass after these fixes.
- KD-tree vs brute-force tie-breaking in `copy_attribute` was not tested.
- `get_property_from_object_path` and `bounds_from_mesh` were reviewed by reading only, since they need scenes and meshes.
- Behaviour tooling note: the gdUnit4 CLI here stops a suite at its first *failing* test, so a red suite hides the cases after the first failure. Error-type failures do not stop it.
