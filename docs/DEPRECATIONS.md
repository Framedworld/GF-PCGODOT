# Deprecations and breaking changes

This page lists what was removed, renamed or changed in meaning in the
`flow_nodes_editor` addon, so projects that vendor it (GodotJC, Black Lantern Tactics
and others) know what to check when they update. Newest entries first. The policy
for future changes is at the end.

When you update a vendored copy, work through every row dated after your last sync.

---

## 1. Removed or renamed symbols

| Symbol | Status | Replacement | Since |
|---|---|---|---|
| `GDRTreeGD` (`addons/flow_nodes_editor/gdr_tree_gd.gd`), the GDScript AABB-overlap fallback | **Removed** as dead code | The native `GDRTree` class (`native/src/gd_rtree.*`); `GDKdTree` for nearest-neighbour queries. Both need the GDExtension binary for your platform. Guard with `ClassDB.class_exists("GDRTree")` if you have to run without it. | `8e53dcb` (2026-06-03) |
| `FlowData.DataType.Vector3` | **Never existed.** Code that references it fails to parse. | `FlowData.DataType.Vector` (always a 3-component vector; the packed container is `PackedVector3Array`). | — |
| Templates `grid_points`, `bl_debug_points` | **Never shipped upstream.** They came from downstream copies. A graph that uses them fails with "Failed to resolve node script for template". | For `grid_points`, the stock `grid` or `grid_fill_bounds` template. For project templates like these, keep the script in a project node directory (see below) or map the old name to a stock template with `FlowNodeRegistry.template_aliases`. | — |
| Templates `bl_*`, `jc_*` in the addon's `nodes/` | **Not part of the addon.** The upstream copy used to contain editor tables naming ~20 `bl_*` templates (colours, a "Black Lantern" add-node category). These tables are now removed. | Move project nodes to a project directory listed in `flow_nodes/node_directories`, and give each node a `"category"` in its `meta_node`. | this release |
| `MAPGEN_DEBUG_ORDER` env var (evaluation-order print for `assemble_map_plan` / `pcg_map_plan`) | **Removed** from `FlowNodeIO._build_evaluation_state` | None. Log from your own node if you need the order. | this release |
| Category and colour tables keyed by template name (`node.gd` `_get_category_hue`, `flow_editor.gd` `cat_map`, `search_add_node_popup.gd` `_CATEGORY_MAP`) | **Changed.** Colour now comes only from `meta_node.category`. Unknown or missing categories get a hash colour. The template tables stay only as a fallback for the add-node menu. | Set `"category"` in `meta_node`. Stock nodes now all declare one. | this release |

## 2. Changed semantics

These changes do not break parsing, but a graph that ran before can now produce
different output. Rows citing a commit subject landed in the current round; the
rows after the `eval_id` row are older changes that were missing from this page.

| Node / API | Before | Now | Since |
|---|---|---|---|
| `sample_spline`, `node` input | Every entry was used as a `Path3D`: a null, freed, non-`Path3D` or curve-less entry stopped the node with a script error. A missing or wrongly typed `node` stream reported "Input are not splines" | Entries that are not a live `Path3D` with a `Curve3D` are skipped with one warning ("skipped N 'node' entries ..."); the remaining paths are sampled as before. A typed empty `node` stream (e.g. a road with no bridges) emits an empty Data with the common, `density` and `seed` streams and no error or warning. The error text is now "Input has no 'node' stream" or "'node' stream must be NodePath/Node typed (got <type>)"; update anything that matches the old message. | `a620722` fix(sample_spline): validate 'node' entries, split the input error |
| `match_and_set`, empty `In` | The empty set went through the matching path: an `In` without the `match_attr` stream (or an `Attributes` table without `match_attr`/`weight_attr`) set an error and produced no output | An empty `In` returns `In` plus a typed, zero-length stream for every `Attributes` column, without checking `match_attr`/`weight_attr`, so downstream expressions can still name the table's columns. Non-empty inputs are unchanged. | `f43e658` fix(match_and_set): keep the Attributes schema when In is empty |
| `$param` bindings and overrides naming a Dictionary entry | A binding named `"args/<key>"` (or, on an Expression node, a bare `args` key such as `"theme"`) logged "binds unknown setting" and was ignored; an override key `"node/args/<key>"` logged "matched no node setting" | These now write that entry of the Dictionary setting (`"<dict_property>/<key>"`, see *Overrides and bindings* in COMING_FROM_UNREAL_PCG.md), coerced to the entry's type. A graph that already carried such a binding or override starts applying it. Other names are unchanged. | `8005e4c` feat(bindings): let bindings and overrides reach Dictionary entries |
| `Data.registerStream`, canonical attribute with the wrong type (`position`, `rotation`, `size`, `normal`, `bounds_min`, `bounds_max` must be Vector; `rotation_quat` Quaternion; `density`, `steepness` Float; `seed` Int) | Overwrote the stream with a "Stream name conflict" warning, so a Float `rotation` replaced the Euler stream and broke orientation downstream | **Refused**: `push_error`, returns the error string, the existing stream is kept (`FlowData.CANONICAL_ATTRIBUTE_TYPES`). `Data.scalar` and runtime graph inputs named like a canonical attribute take its numeric type (`{"density": 1}` registers Float); the output node and the graph-input feed skip a port-name alias that would mistype a canonical attribute. Well-typed graphs are unaffected (golden and seed-0 baselines unchanged). No legacy flag: write the value to another attribute name. | `38e203c` feat(pcg): registerStream refuses canonical attributes with the wrong type |
| Owner-less evaluation from `@tool` scripts in the editor (`require_input`, `reportMissingOwner`, 17 nodes that tested `ctx.owner == null and Engine.is_editor_hint()`) | Treated as an editor preview: missing inputs and the missing owner were silent and the node emitted empty Data | Only the editor dock's context sets `EvaluationContext.preview`; `FlowNodeBase.is_ownerless_preview(ctx)` (preview and no owner) is the silent case. Any other owner-less evaluation, `@tool` or not, reports the documented errors (`"<Input> not connected"`, `"<Node> needs an owner node; ..."`). The editor dock behaves as before. | `15b26d5` feat(pcg): explicit EvaluationContext.preview instead of owner == null in the editor |
| `$param` bindings whose parameter is absent from the inputs, `runtime_params` and `variables` | Kept the saved setting value | Takes the default of the graph's own declared input of that name (`graph.in_params`), when there is one; otherwise still keeps the saved value. Only graphs that bind to a declared input change. | `7cb0cf0` feat(pcg): bindings fall back to the graph's declared input default |
| `match_and_set`, points **without** a `seed` stream | Each pick drew from the node-global RNG in point order, so adding, removing or reordering points reshuffled every later pick | Each point's pick is seeded with `FlowData.resolve_seed(null, positions, i, effective_seed())` (position hash, then index), like `transform` and `attribute_noise`. Points **with** a `seed` stream are unchanged. The stock demos feed a `seed` stream, so the baselines did not change. Set `legacy_global_rng = true` on the node for the old draw order. | `c981656` feat(pcg): match_and_set seeds points by position when there is no seed stream |
| `sample_mesh`, `normal` stream (surface samples and face centres) | Triangle normals were `(b - a) x (c - a)`, which points **into** the surface for Godot's clockwise front faces | Normals are `(c - a) x (b - a)` and point outward. The `normal` stream flips sign, and so does anything computed from it (`normal_to_density`, `build_rotation_from_up` fed the normal, ...). Hard-edge detection compares angles between normals, so it is unaffected. Golden and seed-0 baselines were regenerated for the mesh-sampling graphs. No legacy flag. | `ee662ff` fix(pcg): node fixes from production feedback (Black Lantern) |
| `match_and_set`, key matching | A value matched a key only when their strings were equal: `3` (Int) never matched a `"3.0"` key, and the point kept zero-filled attributes | After the exact string match fails, a numeric value (int, float, or a string that parses as one) matches the first numerically equal key (`is_equal_approx`). Bools are not numbers. Points whose keys differed only in formatting now get attributes. | `ee662ff` fix(pcg): node fixes from production feedback (Black Lantern) |
| `expression`, numeric result written into an existing Bool/Int/Float stream of another numeric type | The stream was re-registered with the result's type (a "Stream name conflict" warning), e.g. a bool comparison turned `density` into a Bool stream | The result is converted into the existing stream's type (`true` into a Float stream is `1.0`). Other combinations keep the result's own type as before. | `ee662ff` fix(pcg): node fixes from production feedback (Black Lantern) |
| `merge`, bulks with different column sets | New streams were registered while appending, which raised the stream-length warning | All new streams of a bulk are registered first, then values appended. **No output change**: same streams, order and values, without the warning. | `ee662ff` fix(pcg): node fixes from production feedback (Black Lantern) |
| `copy` (SourceToTargets) `attribute_inheritance`; `sample_points` `inherit_attributes` | Output carried the source attributes only; samples carried no parent attributes | New settings. The defaults (`SourceOnly`, `false`) keep the previous output; `SourceFirst` / `TargetFirst` / `TargetOnly` and `inherit_attributes = true` opt in. | `ee662ff` fix(pcg): node fixes from production feedback (Black Lantern) |
| `scan_nodes` | Returned every matching scene node, including nodes another flow component had spawned (their auto-generated names made the result non-deterministic at runtime) | Skips nodes carrying `flow_owner` meta (generated content), as its scene fingerprint already did. The editor removed generated content before each regen, so editor output is unchanged; runtime scans that ran after another component generated change. | `2bbb8eb` test(pcg): evaluator, loop, subgraph, spawner suites and a golden-output harness; scan_nodes skips generated content |
| Disabled node in a graph evaluated at runtime | `refreshFromSettings` raised "Nonexistent function 'cleanup_multimesh_direct' in base 'Nil'" (evaluator-built nodes have no `draw_debug`); the node still passed its input through | No script error. **No output change.** | `fbc48a5` feat(pcg): runtime API — graph seed, generate/cleanup/regenerate, owner-less evaluation, boundary data helpers |
| Graph seed (`FlowGraphNode3D.seed`, `FlowNodeIO.evaluate(..., seed)`) | Did not exist; every node used its own `random_seed` | With `seed != 0`, every random node seeds from `FlowNodeBase.derive_seed(seed, random_seed)` = `hash([seed, random_seed]) & 0x7fffffff`; subgraphs inherit the seed and loop iteration `i` runs with `derive_seed(seed, i)`. With `seed == 0` output is identical to before (`tests/runtime/seed_zero_backcompat_test.gd`). | `fbc48a5` feat(pcg): runtime API — graph seed, generate/cleanup/regenerate, owner-less evaluation, boundary data helpers |
| Links into a node's **parameter** ports (exposed settings) at runtime | `evaluate_graph` did not restore `args_port`, and assigning the link to `node.inputs[to_port]` past the flow inputs failed with an out-of-bounds error, so that node did not run and the wired value was never used | The wired port is restored and `node.inputs` grows; the node runs and the wired value beats overrides, bindings and the saved value, as in the editor. Graphs with such links now produce output (golden baseline regenerated in `2bbb8eb`). | `9417d63` feat(pcg): per-instance setting overrides and $param bindings; honour wired parameter ports at runtime |
| `distance`, **unwired** Input B (`get_input(1) == null`) | Some downstream copies treated it as an empty target set and passed the points through with every distance at 1.0 ("infinitely far"). | **Error**: `"Input B not connected"`. In the editor preview with no owner, the output is empty. A connected but **empty** B still takes the far-fill path (every distance 1.0). | `a39ba87` (2026-06-10) |
| `attribute_filter_range`, numeric mode, String attribute with a value that does not parse as a float | The node aborted with an error, and neither output was produced. | That point goes to **Outside**. The other points are still filtered. Non-numeric stream types (Resource, NodePath, ...) still error. | `5a143f6` (2026-06-10) |
| Default node seed | `randi()` per node | Fixed `12345`. Graphs are deterministic by default, as in UE. | `5a143f6` |
| Per-point randomness (`transform`, `attribute_noise`, `attribute_random`, `select_points`, `mutate_seed`) | Came from one node-global RNG in point-index order | Uses a per-point seed from `$Seed`, then the position hash, then the index. Results no longer shift when point order or count changes, but they differ from the old output. | `980dc82` (2026-06-21) |
| Size→bounds generators (`sample_spline`, `sample_points`, `split_splines`, `subdivide_segment`, `create_surface_from_*`) | Wrote the sampling extent into `size`, which spawners apply as scale | Write **unit scale** and put the extent in `bounds_min`/`bounds_max`. Set `legacy_scale_from_extent = true` on the generator to get the old look (see [demo_visual_parity.md](demo_visual_parity.md)). | `03c2826`, `e6aea74` (2026-06-21/22) |
| Spawned-node `flow_owner` meta (`spawn_meshes`, `spawn_nodes`, `spawn_scenes`, `create_spline`, ...) | A `String`: the spawning node's name | A `Dictionary` `{ "component": <FlowGraphNode3D instance id>, "node": <node name> }`, so two components that use the same graph do not clean up each other's output. Cleanup still accepts the legacy String form, so scenes saved before this change clean up. Code that **reads** the meta and compares it to a String has to handle both shapes. | this release ([RUNTIME_API_P0.md](RUNTIME_API_P0.md) §5) |
| `EvaluationContext.eval_id` | Some projects used it to pass a seed into nodes | An evaluation counter only, never a seed. Pass the seed as `FlowGraphNode3D.seed` or `FlowNodeIO.evaluate(..., seed)`. With `seed == 0`, output is identical to before. | this release ([RUNTIME_API_P0.md](RUNTIME_API_P0.md) §2) |
| `runtime_params` across nested evaluations (`subgraph`, `loop`) | The child context got the parent's params plus `__eval_depth` (the nesting depth, injected since `4f8c201`, 2026-06-03), and nothing flowed back | After a nested evaluation, its `runtime_params` are copied back into the parent context, except the local keys (`__eval_depth`, `seed`, `debug_enabled`, `flow_analyze_node`, `flow_suppress_*`) and the keys passed to that invocation. Added in `e0a2804` (2026-06-07), silently a no-op after the phase refactor `d270e34` (2026-06-13), restored in `bfa7e28`. A param set inside a subgraph is visible to the parent's later nodes; never reuse one params Dictionary for two evaluations. | `bfa7e28` (2026-06-14) |
| `output` (single port), alias stream under the port name | Registered the main stream's container with the port's **declared** `data_type`, so a Float stream behind a Vector-typed port became a mistyped stream that crashed type-strict readers such as `filteredStream` | Registered with the main stream's actual type. No change where the two agree. | `c6b8e7b` (2026-06-13) |
| `Data.registerStream(name, container, data_type)` | The type of a packed container was always inferred from the container; the `data_type` argument was ignored (a `PackedFloat32Array` declared Int stayed Float) | The declared type is used; inference only happens when `data_type` is `Invalid`. Callers that declared a type other than their container's now get that type. | `cac340b` (2026-06-13) |
| `noise`, `noise_type` ValueCubic / SimplexSmooth | ValueCubic produced FastNoiseLite `TYPE_VALUE` and SimplexSmooth produced `TYPE_SIMPLEX` | ValueCubic uses `TYPE_VALUE_CUBIC` and SimplexSmooth `TYPE_SIMPLEX_SMOOTH`, as named. Graphs using these two types get different noise. No legacy flag. | `5a143f6` (2026-06-10) |
| `build_rotation_from_up`, reference axis | The secondary axis passed to `basisFromNormal` was `Vector3.UP`, or `Vector3.RIGHT` when `abs(up.dot(UP)) >= 0.99` | Always `Vector3.UP`; `basisFromNormal` itself switches axis only when `abs(n.dot(UP)) > 0.999`. Up vectors between about 2.6° and 8.1° from vertical now build their yaw from UP instead of RIGHT. The node also reads a broadcast (length-1) up-vector attribute and errors on a non-Vector or wrongly sized one instead of crashing. | `5a143f6` (2026-06-10) |
| Execution roots, `subgraph` nodes | Every `subgraph` node (`is_final`) was an execution root, so it always ran, and roots were visited in node order | A subgraph that has wired inputs **and** downstream links runs only when a root (output, debug/inspect node, other final node) depends on it. A subgraph with no inputs, or with no consumers, is still a root. A subgraph whose consumers reach no output no longer runs (its spawns disappear), and execution order can change. | `b478c5e` (2026-06-07) |

## 3. Graph format

| Change | Effect | Since |
|---|---|---|
| `FlowGraphResource.data["version"]` is now `2` (was `1`; data without the key counts as `1`) | `FlowGraphMigrations.migrate` upgrades old data when the editor loads it, at runtime (in memory only) and on paste. Loading a version-1 graph in the editor marks it dirty, and the next save writes version 2. An older addon ignores the version and still loads version-2 data, because version 2 changed no settings keys. | this release |
| Project node directories come from the project setting `flow_nodes/node_directories` | `FlowNodeRegistry.register_node_directory` still works. The setting removes the need to call it before every evaluation and editor load. | this release |

## 4. Policy from here on

1. **One release of soft deprecation, then removal.** A release is a bump of
   `version` in `plugin.cfg`. Whatever is renamed or removed keeps working for one
   release through a shim that calls `push_warning` once per process and names the
   replacement. The following release removes the shim. Every deprecation is listed
   on this page when it lands, with the release that will remove it.
2. **Renamed templates** get an entry in `FlowNodeRegistry.STOCK_TEMPLATE_ALIASES`
   (`"old_template": "new_template"`). `FlowNodeRegistry.get_node_script_path` and
   `FlowGraphMigrations.migrate` resolve the alias when the old script no longer
   exists, and warn once per old name. Re-saving the graph writes the new name.
   Projects can add their own aliases at startup:

   ```gdscript
   FlowNodeRegistry.template_aliases["bl_debug_points"] = "grid"
   ```

   An alias never replaces a template that still has a script, so a project that
   keeps its own copy of an old node keeps using it.
3. **Renamed or reinterpreted node settings** get a `FlowGraphMigrations` entry and a
   `CURRENT_VERSION` bump. Graphs are upgraded on load, so no setting value is
   silently dropped. See "How to add a migration" in the
   [addon README](../demo/addons/flow_nodes_editor/README.md).
4. **Semantic changes** (same inputs, different output) are listed in section 2 with
   the old and new behaviour. Where it is cheap, they ship with an opt-in setting
   that restores the old behaviour (as `legacy_scale_from_extent` does).
5. **Project-specific code never goes into shared addon files.** Category, colour and
   search terms come from `meta_node`. Project nodes live in project directories.
